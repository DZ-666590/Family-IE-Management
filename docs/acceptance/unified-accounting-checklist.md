## 验收口径

系统记录人工同步的家庭财务，不代替银行执行付款，也不声称核实外部余额。正式资金操作以账内已确认的账户余额为依据，不允许隐含透支。

- 现金、资产、贷款本金、收入费用和期初净资产通过平衡分录对应；业务状态与分录同一事务提交。
- 期初、放款、内部转账和还款本金不计入收入/费用；放款、还本单列融资现金流，贷款利息单独记录为费用。
- 期初余额是开账日开始时的余额，之后的现金活动另行累计；不能把更早的活动再叠加到该快照上。
- 更正保留原始凭证和冲销记录。删除业务展示记录不等于删除经济历史。
- 页面预览不是付款授权，后台必须在提交时读取并校验数据库当前状态。

## 已明确的边界

零余额不等于尚未初始化。旧记录没有对应新账时，不自动推测资金来源或历史本金分配。

还款确认按待还期次顺序进行，实际还款日期不能早于已记录的后续付款；本轮不提供已付款历史重排或贷款付款冲销。提前还款处理账内本金，不代表银行最终结清金额。

投资交易仅支持同一账户/证券尾笔的财务更正或撤销；存在后续成本依赖时明确只读。资产估值按日期顺序追加，同日保留多条记录；更早估值改写与处置撤回不在本轮开放。

资产处置账面损益是处置对价与处置前账面价值之差，不等于自最初购买以来的累计投资回报。例如购入 100、估值到 200、以 200 处置，处置账面损益为 0，此前累计资产估值变动 100 单独保留，用于解释净资产增加。这里借鉴了 [IAS 16 第 71 段的处置差额定义](https://www.ifrs.org/content/dam/ifrs/publications/pdf-standards/english/2022/issued/part-a/ias-16-property-plant-and-equipment.pdf?bypass=on)，不表示本项目全面实现 IFRS 或税务会计。

开发数据清理与结构迁移分离：备份只保存在受限运维位置，经过恢复核对后才清理授权范围；新版本迁移不包含自动删除业务数据。公共文档不保存服务器连接信息、凭据或数据库备份。

## 实施裁定与代价

| 裁定 | 理由与代价 |
| --- | --- |
| 保留账户、分类和证券定义，清空金融金额与业务记录 | 缩小删除范围；如果不再需要旧标签，需要另外明确清理 |
| 展示读取快照，付款采用锁定当前读 | 避免所有浏览查询持锁；展示可能短暂落后，不能用于授权付款 |
| MySQL 证券目录共享锁，H2 采用有序锁定替代 | 避免目录锁死锁；H2 并发特征不同，必须另测 MySQL |
| 已确认死锁回滚后最多重试三次完整业务 | 维持事务原子性；极端争用下仍可能返回冲突 |
| 转账仅限所有者/管理员写入 | 延续账户管理权限；普通成员需要管理员协助 |
| 缺报价按剩余账内成本估算并明确标记 | 不遗漏所拥有的资产；估算不等于真实市值 |
| 期初按开账日开始时的余额处理 | 防止历史收支双计；补录更早历史需要真实前移开账日期和金额 |
| 还款按期次顺序，实际付款日期不倒退 | 保护已有本金分配；本轮不支持插入更早付款后重算全部历史 |
| 投资仅改尾笔，估值顺序追加 | 不静默改变后续成本；更早历史更正需要后续完整重算能力 |
| 处置账面差额与累计资产估值变化分开 | 不重复计入财富；该差额不是自原购买日起的累计投资回报 |
| 最多 24 个历史日期只读重算 | 与回溯更正后的账本一致；读取成本增加，若需要“当时所见”应另设明确口径 |
