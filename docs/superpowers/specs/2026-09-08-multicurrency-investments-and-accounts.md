# 港美股记账、汇率表与账户分类设计

状态：设计待书面确认，尚未实现或部署。2026-09-08。

用户已认可方向：港美股完整投资记账、账户品牌化分类；本次补充汇率表。
代码基线：`codex/family-finance-stage-2`，`22ed0c3`。保持现有分支，不再新建分支。

## 1. 用户得到什么

- 「记一笔投资」统一提供 A 股、港股、美股搜索选择，无需自行注册证券；支持期初持仓、买入、卖出、分红与费用。
- 账户创建直接选择现金、银行卡、支付宝、微信、其他钱包；账户列表、付款选择器统一呈现类别与图标。
- 现金、银行、其他钱包及投资账户可使用 CNY、HKD、USD；支付宝、微信余额本轮只用 CNY，不暗示连接真实支付平台。
- 投资页面新增「汇率」页签；家庭总览、账户总额、投资组合按人民币显示折算结果，同时保留原币明细。
- 跨币资金移动通过「记录换汇」完成，记录用户在银行或券商实际发生的换汇，不执行真实转账或交易。

不增加独立侧边栏入口，不添加与业务无关的说明小字。状态、币种和错误原因属于必要信息。

## 3. 汇率表与数据来源

### 3.1 用户界面

表格按人民币为基准，展示：币种、`1 USD/HKD = x CNY`、汇率日期、来源、状态。提供刷新、历史日期查询和最近 30/90 日历史列表。CNY 固定为 1。

金额默认两位小数；汇率默认六位、详情最多十二位；证券单价和平均成本保留业务需要的额外精度。接口传递十进制字符串，不依赖 JavaScript 浮点数做账务运算。

家庭成员可读，OWNER/ADMIN 可请求刷新；刷新有服务端限流与并发合并。普通成员无权修改全局参考汇率；本轮不提供任意手改参考表功能，实际成交汇率在换汇流水中记录。

### 3.2 Build vs Reuse

| 候选 | 取舍 |
| --- | --- |
| Frankfurter v2（开源，可自托管） | 选择公共 API，并指定 `providers=ECB`，避免默认混合多个来源；无需用户申请密钥 |
| ECB 官方 XML 日汇率及历史数据 | 保留为同源后备适配方案；需要解析、交叉换算和安全 XML 配置，首轮不同时接入 |
| HKMA 官方每日汇率 API | 数据源备选，明确单位为每单位外币折合 HKD；不同来源定义不完全相同，不静默混合到 ECB 批次 |

复用数据 API，自己实现小型 Java 提供者接口、持久化、精度规则与展示；不自建报价引擎，不引入新行情运行时。第一阶段不增加自托管服务。

官方资料：

- [Frankfurter API](https://frankfurter.dev/)：日汇率、历史查询、指定 provider、免 API key；公共 API 仍有防滥用限速。
- [ECB 参考汇率说明](https://www.ecb.europa.eu/stats/policy_and_exchange_rates/euro_reference_exchange_rates/html/index.en.html)：参考用途，不是交易成交汇率。
- [HKMA 每日汇率字段定义](https://apidocs.hkma.gov.hk/documentation/market-data-and-statistics/monthly-statistical-bulletin/er-ir/er-eeri-daily/)：包括 USD、CNY 与单位说明。

本轮本机只读探测已取得 Frankfurter 的 CNY→USD/HKD 响应；这不等于已验证服务器可达性，也不保证后续可用性。上线前必须从服务器探测。

### 3.3 持久化与故障规则

- 保存不可变汇率批次及观察值：provider、base、quote、rate `DECIMAL(30,12)`、effectiveDate、fetchedAt、payload hash、版本。
- 一个折算批次必须使用相同来源与日期的 CNY、HKD、USD 关系；必要交叉换算记录路径，内部使用 BigDecimal/DECIMAL128，再明确舍入。
- 同日来源修订追加新版本，不覆盖已经被流水或快照引用的记录。重复抓取相同值复用记录。
- 定时每日抓取，失败有限退避；只读查询使用数据库缓存，不在持有账本写锁时联网。
- 历史查询只能使用不晚于目标日的有效汇率；不使用今天汇率回填过去，缺失时可异步补抓历史数据。
- 表中明确“截至某日”，不把日参考价标成实时汇率。首轮以超过 4 个自然日标记过旧，这是产品阈值而非金融规则；节假日也显示真实日期。
- 抓取失败保留旧批次并显示刷新失败；超过阈值的估值可显示为过期估算。完全缺失则折算值为空，显示原币金额与未折算项数量，不回退为 0 或 1。
- 所需任一币种缺失时，不输出貌似完整的家庭总额或占比；提供“已可折算小计 + 待折算明细”。已闭合零余额不因历史行情缺失被误报。

## 4. 原币账本与实际换汇

### 4.1 普通记账

每个现金账户、投资账户及证券具有明确币种；账户产生账务后不得改币种。投资账户只能关联同币种资金账户。买入必须校验本金加费用后的可用余额；卖出、分红入同币种账户；期初持仓不扣现金。

每条分录记录币种；每个账本科目固定币种，公共收入、费用、权益和换汇清算科目按币种隔离。旧科目和历史分录补 CNY，保留原编号与原金额。凭证按币种分别借贷平衡，不允许用“1 USD 借方”和“1 CNY 贷方”抵消。

贷款、实体资产本轮仍为 CNY，所有相关付款入口及后端均拒绝外币账户并说明原因。外币普通收支、同币互转、投资流水均保留原币；预算、周期账单、年度统计等必须明确采用人民币历史折算或显式限定 CNY，不能直接混加。发布验收采用前者用于已发生的外币收支；周期规则本轮保持 CNY 并约束账户币种。

### 4.2 换汇一次确认

用户选择转出和转入账户，填写实际转出本金、实际到账金额、转出币种手续费及日期。系统推导实际汇率；参考汇率只作对比，不自动代表成交价。两个账户必须是同家庭、不同币种、已初始化、未归档账户。

例（纯示例，非行情）：转出 CNY 7,000，本金；到账 USD 1,000；另收 CNY 10。预览明确 CNY 共扣 7,010、USD 入账 1,000。

- CNY 分录：贷现金 7,010；借 CNY 换汇清算 7,000；借 CNY 手续费 10。
- USD 分录：借现金 1,000；贷 USD 换汇清算 1,000。
- 两组分录关联同一换汇来源，在现有家庭锁、幂等键和数据库事务中完成；任一步失败整笔回滚。
- 清算科目不是用户资产，不计入现金或净资产；换汇本金不计收入/支出，手续费计支出。参考估值差异不自动制造一笔现金盈亏。
- 更正与冲销沿用追加冲销记录，不删除历史。冲销会校验到账款是否已经花掉及历史余额；不足则整笔拒绝。请求摘要涵盖双边金额、币种、费用、账户和日期。
- 不自动换汇买股；用户先换汇入账，再用已有外币余额记投资，避免未经确认扣人民币。

### 4.3 精度及历史折算

所有金融计算使用 BigDecimal；CNY/HKD/USD 实际入账金额按两位结算。单价至少支持六位、数量沿用四位并校验边界；计算乘积后统一结算舍入，不提前将单价截成两位。需检查迁移中旧整数分生成列的兼容和金额上界。

实际交易与收支保存当日可用参考汇率的不可变引用和人民币报告金额；更正追加新版本。历史人民币成本按各次投入的历史折算累积；卖出按与原币一致的移动平均成本方式分配人民币历史成本，尾差在最后清仓时结清。

当前市值用最新有效汇率折算；人民币收益不能把所有历史利润直接乘今天汇率。原币收益与人民币收益分别展示，后者可能包含汇率变化。历史汇率缺失时不阻断同币真实现金与持仓记账，但明确报告不完整；补齐后追加折算版本，保留旧快照，不静默重写既有确认值。

## 5. 证券搜索与持仓

- 搜索采用“市场 + 名称/代码”单一选择组件；市场切换清空旧选项、取消或隔离旧请求，防止异步串市场。
- 服务端以市场、交易所、规范化代码唯一识别证券，并根据可信目录持久化；前端不能自由提交币种或借用另一市场的代码。
- 港股只接入当前支持币种 HKD 的证券，美股 USD，A 股 CNY；其他币种的目录条目明确不支持，不冒充 HKD。不覆盖 ETF、衍生品等未验证范围。
- 行情页选股后可进入记买入；自动带入证券、市场和币种，筛选同币投资账户；无匹配账户时在流程内引导新建并返回草稿。
- 行情是日期明确的参考价，可用于填表参考，用户需核对实际成交价。港美股估值复用已验证未复权日线，不以复权图表价格修改成本。
- 汇总响应和 CSV 导出包括市场、原币、原币金额、人民币折算金额、汇率日期、价格日期与缺失状态；前端不能只靠货币符号推断币种。
- 公司行动自动处理不在本轮；若出现拆股等情况，应提示人工核对，不声称已自动维护复权持仓。

## 6. 账户视觉分类

复用 `walletProvider`、`bankName`、`cardLastFour`，不新增与钱包平台重复的账务类型。账户创建用可键盘操作的图标卡片，支付宝蓝、微信绿、现金/银行使用现有图标体系；旧钱包保留“未细分”，用户可手动设置。

图标采用来源和使用条件可核对的本地 SVG 静态资源，统一尺寸、留白与圆角底板；查证品牌素材后再落地，不从不可信 HTML 注入 SVG，不加载第三方追踪资源。没有许可明确的素材时使用清晰文字徽标，不伪造官方授权。

建立共享 AccountIdentity/AccountPicker 展示组件，覆盖账户列表、投资资金选择、付款预览及初始化向导；不能只给一处加图标。图标旁始终有文字和币种，无障碍名称不依赖颜色。银行未指定品牌时使用通用银行图标，不猜测。

## 7. 实现拆分、兼容和验收

建议按依赖实施，但不单独上线半套多币种功能：

1. 汇率数据模型、提供者、缓存、历史表和状态组件。
2. 账本币种维度、账户约束、实际换汇及幂等/冲销。
3. 证券身份、港美股交易、价格精度、持仓历史折算。
4. 所有受影响报表、净资产快照、CSV 与前端货币格式化；账户分类图标同步落地。
5. 数据迁移验证、集成验收，再推送 CI/CD。

保留所有人民币记录、用户 IDE 文件和原分支；只提交本任务文件。新功能未完整可用前服务端关闭外币创建入口，不能只靠前端隐藏。

必须通过：

- 已有纯 CNY 家庭在迁移前后余额、收益、预算、贷款及幂等重放完全一致。
- USD/HKD 买入确实扣同币账户，余额不足/币种不匹配/其他家庭账户全部拒绝，失败无任何部分入账。
- 汇率正反方向、交叉换算、周末、来源缺失、过旧、未来数据、极小余额、尾差、超大金额均覆盖。
- 两账户换汇成功、失败回滚、重复提交、更正、到账款已使用后的冲销均覆盖。
- 美股与港股同代码不同证券；查询市场切换不串结果；小数单价不会被截掉；行情失败仍可按实际成交价记账但估值标缺失。
- 当前折算不改历史成本；历史查询不引用未来汇率；缺少价格与缺少汇率分别显示。
- 新账户卡片、历史未分类账户、所有付款入口和移动端/键盘操作一致。
- H2/MySQL 迁移与针对性测试通过；不启动本地业务服务，不操作真实用户资金作测试。
- 发布前备份，验证云端汇率源可达；CI 通过和线上版本、健康检查分别确认。新币种写入后旧版程序不保证可安全回退，需前向修复方案，不能直接回滚旧 JAR 继续写账。

## 8. 待确认的范围选择

本设计把汇率表定义为“可追溯的参考估值表”，把实际换汇定义为独立手工资金记录；不做银行连接、不自动兑换、不做保证金或借款买股。用户确认本文后再编写实施计划和修改业务代码。
