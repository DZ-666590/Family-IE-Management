# 多币种投资与汇率

## 使用流程

1. 在账户页选择现金、银行卡、支付宝、微信或其他钱包。现金、银行卡和其他钱包支持 CNY/HKD/USD；支付宝、微信余额为 CNY。确认真实期初余额与日期，零余额也需确认。
2. 投资账户关联同币种资金账户。创建投资时可直接切换 A 股、港股、美股并搜索选股，不需要手工注册证券。没有对应账户时，可在弹窗内建立资金账户、投资账户后回到原草稿。
3. 已有持仓使用“期初持仓”，不再次扣现金；实际新买入扣减对应现金账户，卖出、分红按原币回到账户。买卖单价最多六位、数量最多四位小数，实际入账金额结算到两位。
4. 跨币资金移动使用“账户互转”页面下的“换汇记录”，填写实际转出本金、到账金额和转出币种手续费。一次提交完成双边记账；不执行真实银行或券商交易，也不自动按参考汇率扣人民币买外币股票。
5. 投资页“汇率”提供当日/历史参考表、30/90日记录范围和手动更新。系统启动后缺少汇率会自动尝试初始化，之后每日上海时间23:10和00:10更新；初始获取失败会按小时重试。网络故障保留旧快照并标记状态。

## 统计口径

- 账户余额、每笔资金流水和持仓明细保留原币；组合总览、家庭净资产折成人民币。不同币种不直接相加。
- 参考汇率来自 Frankfurter 的 ECB 数据，统一保存为“1单位原币折合人民币”。[ECB说明](https://www.ecb.europa.eu/stats/policy_and_exchange_rates/euro_reference_exchange_rates/html/index.en.html)明确它是参考汇率，不是银行成交价。
- 实际换汇以填写的双边金额为准，费用单列。换汇本金不算收入或费用。
- 人民币持仓收益使用记录日期的历史参考汇率与移动平均成本，包含汇率变化；原币收益独立展示。期初持仓按填写的期初日期折算，不推算用户未提供的历史实际换汇成本。
- 收支、预算和年度统计按已入账原币收入/费用的发生日参考汇率折算；单独的汇率估值波动不自动记成现金收入。
- 缺少当前汇率时，完整总额留空并列出已折算小计和原币待折算项。缺少发生日汇率时，人民币成本/收益或收支统计标记待补充，原币业务不丢失，不退回1:1汇率。
- 历史凭证引用的汇率不会因今天的汇率变化而改写。补齐缺失参考汇率只填空白引用；新修订追加保存。净资产历史区分当前口径重算值与已保存快照，重复生成改变值时保留版本。
- 收支CSV带币种及人民币参考金额、汇率与日期；投资交易支持独立CSV导出，保留市场、交易所、原币单价及参考折算信息。
- 本轮投资范围为普通A股、港币港股和美元美股；其他计价币种的港股只读，不冒充港币。贷款、实体资产与周期规则仍使用人民币账户。

## 部署保护

新增迁移为V29–V37；只追加迁移，不修改已发布V1–V28、不重置业务数据。

发布继续使用Stage2 CI/CD。应用读取包内`static/deployment.json`及部署接收器的`/var/lib/family-finance-ci/current.json`，只有两者commit相同，才开放外币创建/换汇及超过两位小数的新单价。

这样首次升级未通过健康检查时，旧版自动回退不会读到新版本才支持的外币或微小单价记录。部署接收器写入成功标记后自动开放，无需人工绕过；前端等待期间定期刷新币种能力。

配置：

- `APP_MULTICURRENCY_ENABLED`：默认true，可关闭新增外币开户/换汇能力，但已有外币记录仍按正确币种读取。
- `APP_FX_SCHEDULED`：默认true，控制汇率初始化、定时更新和缺失引用补齐。
- `app.multicurrency.deployment-state`：默认上述接收器状态路径；运行应用的系统用户须能读取，状态文件不含数据库或API凭据。
- `app.multicurrency.verify-deployed-revision=false`：仅用于不经CI发布的开发/测试环境。不得在首次生产升级时关闭保护。

部署成功且已有新格式数据后，不应手工回滚到V28及以前的旧程序；应前向修复，或按经过验证的完整恢复方案操作，不能仅换回旧JAR继续写账。

## 验证边界

实现包含Java服务/权限/事务测试、前端操作测试和MySQL隔离结构验证。隔离库只使用结构及合成数据，测试完成删除；业务库未变更。真实网页视觉与上线版本检查应在正式授权部署后进行，不能把单元测试或本地构建当作已经上线。
