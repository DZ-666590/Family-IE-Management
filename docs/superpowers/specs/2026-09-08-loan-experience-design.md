# 贷款使用逻辑升级

用户要求按顺序实现五项功能并直接执行，不等待中途设计审批。基于 Stage2 `be4ba9e` 已完成的统一账务实现，不重复上一轮清库；之前的服务器发布仍待 SSH 恢复。本轮不创建新分支。

## 1. 本次贷款购买物

创建贷款的关联资产选项增加“本次贷款购买物”。该选项明确表示贷款人直接支付购买款，不经过家庭现金；普通现金放款/关联已有资产仍保持原流程。

- API 增加 `createPurchasedAsset`，为 true 时要求 `fundingMode=FINANCED_PURCHASE`、linkedAssetId/disbursementAccountId 为空。
- MORTGAGE→PROPERTY（房产N），CAR→VEHICLE（车辆N），OTHER→OTHER（其他资产N）。名称按类别加数字自动生成并保证同家庭不冲突。
- 购入价值、当前价值和账内初始价值均为贷款本金；取得日、账务日期为贷款 accountingOn；非必要信息为空。必填系统字段取实际家庭、操作人、类型和日期。
- 不捏造面积、地址或车型：自动资产允许无子类型资料，明确 `detailsPending=true`。普通手工资产的完整校验不放松；资料可在资产页面补齐，补齐不产生新的金融分录。
- 一个事务保存贷款、自动资产、关联和单一平衡凭证：借 ASSET、贷 LOAN。资金账户余额不变；不是期初收入、不是现金放款。不再另过一笔重复资产取得凭证。
- 来源为 `LOAN_FINANCED_PURCHASE:<loanId>`；资产返回实际取得来源类型/ID，审计链接不可硬编码 ASSET_ACQUISITION。
- 保留不可变的自动购买物来源关联。之后不能从贷款 PATCH 单独改本金、账务日期、放款账户或换掉购买物；未付款前仍可更正利率、期限和计划，其他安全元数据沿用原规则。

## 2. 计划本息与剩余金额

卡片及信息面板并列展示 `scheduledRepaymentTotal`（当前有效计划总金额）、`remainingRepaymentTotal`（待还期次本金+利息）及原有 currentPrincipal。另展示累计已还现金 `paidRepaymentTotal`。

- 当前有效计划总金额 = 已按期支付现金 + 已提前支付现金 + 当前 PENDING 期次本息。CANCELLED 期次不重复计入；结清事件只计一次。
- 不从前端已加载的50行估算总额。后端按全量有效记录、整数分计算；修改或重排后及时刷新。
- 计划剩余本息不等于提前结清金额；两种用途必须分开标注。

## 3. 一次结清剩余贷款

“一次结清”打开确认面板，默认今天、明确付款账户，展示本金、到期未付利息、可选补录的本次实际利息和最终扣款。它是一次确认的完整操作，不是循环发送每期确认请求。

- 默认结清利息为 paidOn 当天及之前 PENDING 期次的利息；未到期计划利息不计收。
- 用户可填 `interestAmount` 补录银行实际利息，不能小于账内到期未付利息（利息减免不在本轮）。未提供时使用默认。合同外手续费请按真实发生另记费用，不猜测。
- Quote 返回 `principalAmount`、`dueInterestAmount`、`interestAmount`、`futureScheduledInterest`、`cashAmount`、paymentAccountId/可用余额及 `planToken`。
- POST 使用稳定请求键、付款日期/账户、interestAmount 及 planToken。服务端锁定当前贷款、期次、账户，重新计算并核对 token；计划变更时拒绝旧报价并要求重新核对，不能按旧预览暗中增加扣款。
- 一次复式付款：借 LOAN 本金、借 EXPENSE 本次利息、贷所选 CASH 合计。本金归零，贷款 CLOSED，原已付期次保留，剩余计划取消并可追溯到结清事件。
- 复用 LOAN_PREPAYMENT 来源/记录，新增操作类型 PAYOFF 与本金/利息信息，避免另建独立付款账。历史旧事件按本金、零利息兼容，不改写旧分录。
- 原提前还款接口若请求全额本金，不能继续绕过到期利息：有待付到期利息时引导一次结清；无到期利息可安全走同一结清机制或要求新确认，不得无提示多扣现金。

## 4. 指定现金账户与原子性

所有按期、部分提前及一次结清均支持选择实际付款账户（未指定兼容原贷款默认账户），不汇总其他现金账户、更不使用净资产判断可支付性。临时选择不修改以后默认账户。

延用 household-first 当前锁、已确认期初/日期/归档检查、逐日现金非负、本金投影一致、同事务业务和分录、完整事务死锁重试及全请求幂等。权限延续原规则：按期由指定用户确认，提前还款/结清由所有者或管理员操作；不是银行代扣。

## 5. 部分提前还款双策略

先提供只读预览，再提交同一方案。`REDUCE_TERM`=缩短还款年限、月供不变；`REDUCE_PAYMENT`=减少月供、期限不变。未指定兼容原 REDUCE_PAYMENT 语义。

- 部分本金金额严格小于剩余本金；日期不倒退。到期未付期次（dueOn<=paidOn）必须先确认，不能在重排时免除其本金/利息。
- 保留旧 PAID/CANCELLED 记录，新计划新编号；原 PENDING 取消，新期次本金合计严格等于新剩余本金。
- 保留原未来到期日序列，不从提前还款日另起一个月；原合同期限/起算日不覆盖，返回当前剩余期数、到期日和采用策略。
- REDUCE_TERM：以原每期本息合计为付款上限，重新计算利息和本金，末期只收余额+当期利息；提前结清后不产生零额期次。等额本息保持原月供，等额本金/自定义保持原逐期金额序列，不伪称原本递减金额是固定月供。
- REDUCE_PAYMENT：等额本息/等额本金沿用现有算法，按新本金、相同剩余期数重算；到期日不变。剩余本金不足每期至少一分时明确拒绝该方案并建议缩期/结清，不生成零本金账单。
- CUSTOM：固定期限方案按原剩余本金分配权重缩放本金（分位尾差归末期）；两种方案的利息均按原该期利息/原期初未还本金的隐含比例作用于新余额，保持原日期与自定义计息结构，不擅自假设月度或零息。它是原计划的账内模拟，实际合同差异需人工核对。
- 预览展示重排前后每期金额、剩余期数、到期日、剩余利息和本次扣款，提交核对 planToken 并在同一事务扣现金、减本金、重排计划。不得把测算“少付计划利息”称为银行承诺收益。

## 技术与验收

- Java17/SpringBoot/MySQL/React/Semi保持不变，前端延续 Clarity 配色和现有 MoneyPreview、草稿保护、按字段报错、请求键及刷新机制。
- 不提交真实服务器信息、凭据、备份或用户 IDE 文件；所有提交用显式路径 `git commit --only -- <paths>`。
- V1–V18 不改，只加新的 MySQL/H2 迁移；无启动清库、无推测回填旧金融数据。只有全部功能接入并验证后才考虑发布；SSH 缺失不阻塞本地实现。
- 验证：自动购买物不多现金/不多资产，重试不重复；2000本金两期100/50利息初始计划2150，付1100后剩余1050/本金1000；结清含到期利息而不收未来利息；不足现金完整回滚；同账户并发不可透支；两种方案本金精确守恒、日期保留、总额不重计。

参考银行公开材料仅用于区分本金、利息及重排概念，不宣称本系统等同某银行合同：[中国银行提前还款测算](https://www.boc.cn/ebanking/bocmbs/mb8/201011/t20101123_1211530.html)、[工商银行贷款合同示例](https://media.icbc.com.cn/agreement/1237977346120626176.html)。
